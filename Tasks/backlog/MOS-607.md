## Architecture Context

### How Detection Works
1. `meeting-detect.sh` streams macOS TCC (Transparency, Consent, Control) log events for camera/mic access
2. Browser tab probe (AppleScript, every 2.5s) checks Chrome/Safari/Edge for meeting URLs
3. Native app probe (every 2.5s) checks running meeting processes + requires TCC mic signal within 60s
4. Lifecycle state machine: first confident signal → `meeting_started`, 30s silence → `meeting_ended`

### The TCC Problem
The detector depends on macOS TCC log signals — these are emitted when an app **requests** camera/mic access through the OS permission system. In automated browser contexts (Playwright, Cypress, CDP), Chrome's `--use-fake-ui-for-media-stream` flag or `grantPermissions()` API bypasses the OS-level TCC dialog entirely, so no TCC signals are emitted, and the detector sees nothing.

**This is the fundamental blocker for automated web E2E testing.** The detector works correctly when a human manually joins a meeting in a real browser — the TCC signals fire, and detection works. But automated tools bypass the OS permission layer.
