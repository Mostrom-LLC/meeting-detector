## Architecture Context

### Detection Pipeline (post-MOS-607, target state)

1. **Rust native module** (`native/src/platform/macos.rs`) streams `com.apple.TCC` log events, parses FORWARD/Granting/AUTHREQ_CTX, enriches by PID (`ps`/`lsof`), normalizes helper apps, attaches Chrome URL when relevant, and emits `MeetingSignal` objects via `detect()`.
2. **`src/detector.ts`** polls `nativeDetector.detect()` every 500ms and runs an independent browser-tab probe (AppleScript every 2.5s) for Chrome/Edge/Safari.
3. **Classifiers** (`browser-platform.ts`, `native-platform.ts`) map signals to platform names.
4. **Lifecycle state machine** (`detector.ts` + `lifecycle/session-timeline.ts`) emits `meeting_started` on first confident signal and `meeting_ended` after silence.

### Key Files

| File | Role |
|------|------|
| `src/detector.ts` | Main detector (~1800 LOC), orchestration + lifecycle |
| `native/src/platform/macos.rs` | Rust macOS implementation (TCC streaming + enrichment) |
| `native/src/detector.rs` | Rust detector core / state machine |
| `native/src/lib.rs` | napi-rs bindings |
| `src/classifiers/browser-platform.ts` | URL/title classifier |
| `src/classifiers/native-platform.ts` | Process classifier |
| `src/lifecycle/session-timeline.ts` | Session timeline |
| `scripts/e2e/live-verify.mjs` | Live verification CLI (use in Task 9) |
